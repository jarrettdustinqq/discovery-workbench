# Discovery Workbench utility test 1 — frozen protocol

Owner: jarrettdustinqq. Scope: retrospective next-hour PM2.5 forecasting, not a deployed warning service or a claim of scientific novelty. This protocol is committed before successful dataset retrieval or inspection of any test outcomes. Preserve this version and all negative results. Do not change application runtime code, main, deployment, schedules, permissions, or billing.

## Decision and alternatives
Determine whether the unchanged 0.1.0 research preview provides useful predictive advantage over established alternatives on separately collected observations. An existing forecast or a compact fitted equation is not an advantage by itself. Air-quality forecasting was selected for measured outcomes, site/time identifiers, a small public download and demanding persistence/tree baselines. A power-plant regression dataset without chronological identifiers offers weaker leakage control; simulated building-load datasets do not satisfy measured-observation requirements. Expected benefit: an auditable accept/reject decision. Downside: one dataset and one region cannot establish broad utility; data latency, missingness and operational costs remain untested.

## Task and eligible observations
Predict PM2.5 at t+1 hour in micrograms per cubic metre from exactly four inputs: PM2.5(t), PM2.5(t-1 hour), PM10(t), and wind speed WSPM(t). No same-hour target or future covariates. Use exact timestamp joins, not shifts after deleting missing rows. Forecast origins must have hour in {0,6,12,18}; the t-1,t,t+1 windows therefore do not overlap between distinct selected origins. Atmospheric serial dependence remains.

Require all four inputs and next-hour target to be finite, nonnegative and <=1e6, with exact neighboring timestamps. No interpolation, imputation, outlier trimming, transformations using test distributions, or filtering on forecast error. Preserve missing/excluded counts, denominators and coverage by site. A row may only be excluded for these frozen eligibility rules. Require at least 2,000 eligible distinct-input development rows and at least 1,000 eligible test rows and 26 nonempty seven-day blocks per test site; otherwise report insufficient evidence, without switching sites.

From eligible development rows, retain the earliest origin for each exact four-input tuple. Rank remaining rows by SHA-256 of the ASCII string 'pm25-utility-v1|' plus timestamp formatted YYYY-MM-DDTHH:MM:SS; retain the 2,000 smallest hashes, then sort by timestamp. Use the unmodified engine's ordered split (expected 1,200 train / 400 validation / 400 internal audit rows). Assert actual train origins precede validation origins, validation precedes internal audit, and neighboring windows do not cross these boundaries. Abort rather than silently fix a split failure. The internal 400 are not the external test.

## Established baselines
All baseline inputs are identical to the tool's four inputs. Include persistence, yhat(t+1)=PM2.5(t); a training-target-median constant; standardized ridge autoregression with alpha in {0,0.1,1,10,100}; and histogram gradient boosting. Ridge and trees use the exact engine training indices and are selected only by validation RMSE, with lexicographic configuration key for exact ties.

Tree grid: loss in {squared_error,absolute_error}; max_leaf_nodes in {7,15,31}; l2_regularization in {0,1}; max_iter=200; learning_rate=0.05; min_samples_leaf=20; early_stopping=false; random_state=42. Twelve configurations. Also evaluate a practical full-development-training baseline: the same ridge/tree grids fitted on ALL eligible six-hour development origins not later than the latest engine training origin, with target time strictly before the earliest validation origin minus one hour. Select on the SAME 400 validation observations. This prevents the tool's 2,000-row limit from artificially constraining every alternative. Report training counts and compute, and keep equal-data and full-data comparisons distinct.

The primary baseline champion is the single lowest-validation-RMSE baseline across persistence, median, selected equal-data ridge/tree and selected full-training ridge/tree. Select and freeze it before extracting any test station file. Apply nonnegative clipping identically to every model's predictions; report unclipped negative/nonfinite counts. Any nonfinite tool prediction on an eligible test row is a test failure, never a reason to drop that row. Pin dependency versions and record the runtime environment.

## Endpoints, uncertainty and decision
Primary: RMSE in original units, reported per site and as sqrt(mean of the two site MSEs)), so larger cohorts do not dominate. Report all frozen baselines, not just the winner. Secondary: MAE, R-squared, coverage and out-of-development-range input counts. Tail error may be reported only using the training target's 90th percentile as the fixed cutoff; it cannot replace the primary endpoint.

Paired block bootstrap: use seven-day blocks anchored at 2016-01-01 00:00, 4,000 replicates, NumPy default_rng seed 20260915. Resample aligned calendar-block IDs jointly across sites and models, preserving within-block temporal and cross-site association. Report the percentile 95% interval for site-balanced RMSE ratio Workbench / frozen primary baseline. This is a dependence-aware approximation, not proof that seven days removes all dependence.

A useful predictive advantage requires ALL: (1) >=5% lower RMSE than the frozen champion AND persistence at EACH test site; (2) bootstrap upper 95% RMSE-ratio bound <1; (3) no >5% increase in MAE versus either comparator at either site; (4) no invalid predictions, leakage, provenance failures or insufficient coverage. This is an operator-selected screening threshold, not a universal scientific standard. Otherwise: no demonstrated useful advantage; stop tool expansion. Interpretability alone, an internal 'supported' verdict, passing tests, delivery and synthetic recovery cannot rescue a failed primary gate.
